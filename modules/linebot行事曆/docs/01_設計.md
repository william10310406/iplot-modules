### 4.3 解析：只認 version 1，欄位型別嚴格、不認得的欄位忽略

依 `iPLoT-資料格式.md`（version 1），不猜欄位。

- 頂層要是物件、`version == 1`；`events`、`tasks`、`logs`、`moods`、`jots` 要是陣列；`range.from`、`range.to` 要是合法日期。**不認得的欄位（頂層或每一筆）一律忽略**，包括之後會多的「這筆是從 iPLoT 來的」標記。
- 每一筆的欄位與型別照文件：

| 區 | 必要欄位（型別） | 可以是 `null` |
|---|---|---|
| events | `id` `title` 字串；`allDay` `private` 布林；`startDate` `endDate` 日期字串 | `start` `end`（整天活動是 `null`）、`location` `note` `group` |
| tasks | `id` `title` 字串；`done` `private` 布林 | `dueDate` `dueTime` `note` `group` |
| logs | `date` 日期；`private` 布林；`items` 陣列，每項 `title` 字串 | `group`；每項的 `details` |
| moods | `date`；`face` 是 `grin/smile/neutral/worried/cry` 之一 | `text` |
| jots | `id` `date` `text` `createdAt` 字串 | — |

- `moods` 的表情用 `face` 對照 `diary.MOODS`（😄🙂😐😟😢）；`emoji` 欄位忽略，不信它。
- **任何一處型別不對、`face` 不認得、日期不合法，整份拒收**，快取不動，說明哪一區（L06）。
- 時間：ISO 8601 `+08:00`，一律換成台北時間（固定 +8，不看這台電腦的時區）取日期與 `HH:MM`。整天活動：`startDate` 到 `endDate`，**`endDate` 含最後一天**（跟 ICS 的 DTEND 不同），每一天都出現。有時間的活動跨日：每一天都出現；結束時間剛好是 00:00 的，最後那天不算。`endDate` 早於 `startDate` 當作單日。一筆活動最多展開 400 天。
- 快取裡每一筆（events、tasks、jots，與 logs、moods 以日期為鍵）**保留原本的 `id` 與欄位**，不只存顯示用的字（為了之後雙向同步，第 11 節）。

### 4.4 網址與設定檔

**網址規則（`line_url.py`）。** 只收符合下面全部條件的：

- 開頭是 `https://`；
- 沒有帳號密碼（`user:pass@`）、沒有查詢字串（`?`）、沒有片段（`#`）、沒有空白或控制字元；
- 主機是一般的網域名稱（字母、數字、`-`、`.`；可帶埠號）；
- 路徑剛好是 `/j/<token>.json`，`<token>` 只含 `[A-Za-z0-9_-]`，長度 20–128（bot 目前是 40–64；字元集嚴格、長度放寬，bot 改長度時這邊不會壞，L04）。

其他一律拒絕，並說：「這不是 iPLoT 的網址：要以 https:// 開頭、結尾是 /j/<一串字>.json。請私訊 bot『連上iPLoT』拿網址。」錯誤訊息裡**不回顯**使用者貼的內容。

**遮罩。** 畫面、訊息、log 一律用遮過的：`https://<主機>/j/AbCd…wXyZ.json`（token 只留前 4、後 4）。完整網址只存在 `設定.json` 與抓取那一刻的記憶體。

**設定檔格式**（`modules/行事曆 2/設定.json`，之後能再加欄位）：

```json
{
  "資料夾": "/Users/…/Documents/行事曆",
  "LINE": { "url": "https://…/j/….json", "auto_copy": false }
}
```

- `settings.py` 每次寫都是「讀出來、改一個鍵、寫回去」，**保留不認得的鍵**（現在的 `diary.save_root` 整檔覆寫，會洗掉別的欄位，所以改成呼叫它；L05）。之後多的寫入金鑰放 `"LINE"` 底下，不用改格式。
- 先寫同資料夾的暫存檔再 `os.replace`；檔案權限 0600。
- 壞掉的 `設定.json` 當作空的；不會因為它壞掉就整個打不開。

### 4.5 網路（`line_net.py`）

- `urllib.request`，**只用 GET**；加 `Accept: application/json`、`User-Agent: iPLoT-calendar2/0.1.0`（一般的名字，不放任何個人資料；HTTP 標頭要 ASCII，所以不放中文）。
- 逾時 15 秒（跟 iPLoT 其他模組讀 json 一致）；回應最多讀 2 MiB，超過就放棄。
- **不跟轉址**：自己建 opener，遇到 3xx 當錯誤（轉到別的主機會把 token 帶過去）。
- `https://` 驗證憑證，不關；macOS 的 python.org 版沒有根憑證時，改用 `/etc/ssl/cert.pem`（docs/07 第 6 節的做法，自己寫一份，不 import 別的模組）。
- 所有例外都在這一層接住，變成 `LineError(kind, message, retry_after)`。**`message` 是我們自己寫的一句話，不用 `str(exc)`**，因為 `URLError`、`InvalidURL` 的訊息可能含網址，而錯誤回報流程會把錯誤送出去。`HTTPError` 的 `.url`、`.filename` 也不碰。

| 情況 | 顯示的一句話（`{時間}` 是快取的時間） |
|---|---|
| 沒設定網址 | 還沒設定 LINE 網址：到 ⚙ 貼上（私訊 bot『連上iPLoT』拿網址） |
| 404 | LINE 說找不到：網址可能已經重設，請私訊 bot『連上iPLoT』拿新的。顯示的是 {時間} 的快取 |
| 429 | LINE 說請求太多，{n} 秒後可以再更新。顯示的是 {時間} 的快取 |
| 400 | LINE 說日期範圍不對（只能看今天前後 400 天、一次最多 100 天） |
| 405 | LINE 拒絕這種請求（方法不對）。這是程式的問題，請回報 |
| 5xx | LINE 那邊出錯了（HTTP {碼}），晚點再試。顯示的是 {時間} 的快取 |
| 逾時／沒有網路／連線中斷／憑證不過 | 連不上 LINE（逾時／沒有網路／連線中斷／憑證驗證失敗）。顯示的是 {時間} 的快取 |
| 轉址 | LINE 的網址被轉到別的地方，已拒絕 |
| 太大 | LINE 回的資料超過 2 MiB，已拒絕 |
| 不是 JSON、欄位型別不對 | LINE 回的資料格式不對（{哪一區}），沒有更新快取 |
| `version` 不是 1 | LINE 的資料是 version {v}，這一版行事曆 2 只懂 version 1：請更新行事曆 2 |

**429：** 讀 `Retry-After`（秒數或 HTTP 日期），夾在 1 秒到 1 小時之間，沒有就 60 秒；記成 `retry_until`，期間不再送任何請求（打開、翻月、立刻更新都一樣），「立刻更新」鈕顯示還要等幾秒。不是睡著等：頁面照常能用。

### 4.6 抓哪一段、什麼時候抓

- **打開行事曆 2：** 抓一次**預設範圍**（不帶 `from`／`to`：前 35 天到後 70 天）。回應的 `range` 記成一段「已抓過」。
- **「立刻更新」：** 再抓一次預設範圍；如果現在看的月份在預設範圍外，那個月也補抓。
- **翻月／年：** 用 `from`／`to` 補抓**沒有快取的部分**。月：那個月（≤ 31 天）。年：沒快取的月份合併成 ≤ 100 天的幾段，最多 4 段，遇到 429 就停。只抓在**今天前後 400 天內**的部分（以台北日期算）；範圍外的月份直接說「LINE 只提供今天前後 400 天」，不送請求。
- **「同一段時間有快取就不要重抓」：** 快取按「段」存（每段有 `from`、`to`、`fetched_at`）；一段在 24 小時內抓過就算有。預設範圍每次打開都重抓一次，所以只有預設範圍外的月份用這條。
- 一次只有一個請求在跑；翻得很快時，同一段不會送兩次。
- **預覽之外的三條規則**（實作時發現需要的，L13）：
  1. 預設範圍正在抓（或排著）時，翻到它會蓋住的那一段**不另外抓**（不然每次打開、頁面第一次重畫時都多送一個請求）。
  2. **404、405 之後翻頁不再自動補抓**（網址失效、程式的問題：敲 bot 也沒用），要你按「立刻更新」或換網址才再試。
  3. 其他失敗之後，翻頁補抓要**隔 30 秒**才再試。「打開」與「立刻更新」不受這兩條限制。
- 第一次要資料（`month`／`year`／`day` 的第一次呼叫，頁面一打開就是 `month`）排「打開」那一次；之後的 `month`／`year`／`day` 順便排補抓。所以頁面不用自己叫補抓，**沒有 `line_need` 這個方法**。

**背景執行緒（重要）。** 現有的 `Api` 每個方法都拿同一把鎖，頁面的呼叫又排成一條佇列。如果抓網址在鎖裡等 15 秒，這段時間存檔、翻頁全部卡住。所以：

- 抓網址一律在 `line_sync` 自己的背景執行緒上做，**不拿 `Api._lock`**；`Api.line_refresh`／`line_need` 只是排工作、立刻回傳。
- 頁面用 `line_state()` 輪詢（忙的時候每秒一次，不忙就停）；狀態裡有一個 `version` 數字，快取變了就加一，頁面看到變了才重畫（正在打字就不重畫）。
- 要寫日記的動作（複製、自動複製）才拿 `Api._lock`，而且只做本機檔案。`_lock` 是 `RLock`（L14）：自動複製是抓完 LINE 之後在 LINE 的背景執行緒上做的，但在測試與某些排程下會在同一條執行緒、已經拿著鎖的呼叫裡做完。

### 4.7 快取（`line_cache.json`）

放在「行事曆 2」資料夾，0600，先寫暫存檔再 `os.replace`。壞檔當作空的（不丟 traceback）。

```json
{
  "version": 1,
  "account": "<token 的 sha256 前 12 碼>",
  "slices": [
    {"from": "2026-10-02", "to": "2027-01-15", "fetched_at": "2026-11-08T21:45:00+08:00",
     "events": [...], "tasks": [...], "logs": [...], "moods": [...], "jots": [...]}
  ],
  "last": {"at": "…", "ok": true, "kind": null, "message": ""},
  "retry_until": null
}
```

- 每一段的資料就是解析過的原樣（保留 `id` 與所有認得的欄位）。畫面用的時候把幾段合起來，同一個 `id`（或同一個日期的心情）以**較新的一段**為準。
- 一段被較新的一段完全蓋住，就丟掉；最多留 12 段；整段都在今天 400 天以前的丟掉。
- **換網址：** 清掉整份快取（LINE 的資料）。`line_copied.json` 留著，它記的是「已經寫進日記」的事實，不是 LINE 的資料。`account` 只用來判斷「這份快取是不是這個網址的」。
- **清除網址：** 刪網址，也刪快取。確認之後才做。

## 6. 心情的優先順序

「表情」跟「一句話」分開看：

1. 那天你在 iPLoT 選過表情（`心情.txt` 第一行是五個表情之一）→ **用你的**，LINE 的心情不顯示。
2. 沒選過 → 顯示 LINE 的表情和一句話，標「LINE」。
3. 兩邊都沒有 → 什麼都不顯示。

只寫了一句話、沒選表情，算「沒選過表情」：顯示 LINE 的表情，一句話欄位照樣是你的。這個規則只管顯示；**不會把 LINE 的表情寫進你的日記**（除非複製，第 7 節）。

## 7. 複製進日記（做法 A）

這是**唯一**會把 LINE 的內容寫進日記資料夾的地方。

### 7.1 複製什麼、怎麼接

| 日記欄位 | 來源 | 一行長什麼樣 |
|---|---|---|
| `行程.txt` | events、tasks | `10:00–11:00 標題 @地點`；整天 `整天 標題`；備註縮排兩格接在下一行；待辦 `☐ 標題（截止 18:00）`、`☑ …` |
| `看到.txt` | jots | `14:32 小記的字` |
| `做了.txt` | logs | `標題`；`details` 縮排兩格接在下一行 |
| `心情.txt` | moods | 只有當天**表情欄是空的**才填表情；**一句話欄是空的**才填一句話；有的不動（不覆蓋） |

文字欄位：**接在原本內容後面，不覆蓋**。原本有字的話先空一行，再加一行 `── 從 LINE 複製 2026-11-08 21:45 ──`，再接內容。原本是空的就只有那一行標題加內容。

### 7.2 手動（預覽、你按確定）

1. 日檢視底部按「把這天 LINE 的內容複製進我的日記」。頁面先把這天正在打的字存好（沿用現有的存檔）。
2. `Api.line_copy_preview(date)` 不寫任何東西，回「每個欄位會接上什麼」、略過了什麼（私人、已複製過）、這天是不是「公開」、一個 `digest`（預覽內容的 sha256）。
3. 預覽視窗顯示完整文字。**這天勾了「公開」時，寫上紅字警告：「這一天會被『發佈』放上網路，複製進去的 LINE 內容也會跟著」，而且私人項目預設略過。**
4. 你按「確定」→ `Api.line_copy(date, digest)`：重新算一次，`digest` 對不上（預覽之後 LINE 或日記又變了）就不寫，說「內容有變，請重新預覽」。
5. 寫入：`diary.save_day(…, force_snapshot=True)`，寫之前**一定**把舊的存進 `.history/<欄位>-<時間>.txt`（L07），然後重建那一天的網頁（沿用 `pages.rebuild_after_save`），最後把這次複製的項目記進 `line_copied.json`。
6. 完成後頁面重讀這一天，狀態列說「複製了 N 項，原本的內容在 .history」。

### 7.3 自動（每次打開一次）

`⚙` 裡打開「自動複製」之後，**每次打開行事曆 2**，在抓完 LINE 之後做一次：

- **範圍：** 上一次自動複製到的日子（`line_copied.json` 的 `auto_through`）的隔天，一直到**昨天**。你第一次打開開關時，`auto_through` 設成「昨天」，所以只會從**下一次打開之後新增的日子**開始複製，**不會回頭補抓歷史**；更早的日子用手動按鈕。
- **只在這次打開有成功抓到最新資料時才做**；抓失敗就跳過，下次打開再做，`auto_through` 不前進（不拿過期的快取去寫日記）。
- **跟手動一樣的規則，少了預覽：** 同樣的格式、強制先存快照、已複製過的不重複、寫完重建網頁。
- **更嚴：** 私人（`private: true`）項目一律略過；**勾了「公開」的日子整天不自動複製**（L10）。這些要進日記只能你自己按手動按鈕。
- **不碰你正在看的那一天：** 頁面正開著某一天的日檢視時，那一天略過（不然頁面的舊文字框會在下一次存檔時把它蓋掉），`auto_through` 停在它前一天，下次打開再處理。
- 結果寫在狀態列：「自動複製了 3 天（略過 2 項私人、1 個公開的日子）」。

### 7.4 已複製的紀錄（`line_copied.json`，在「行事曆 2」裡）

```json
{ "version": 1, "auto_through": "2026-11-07",
  "items": { "event:E123:2026-11-07": "2026-11-08T21:50:03+08:00", "jot:J9:2026-11-07": "…" } }
```

鍵是 `種類:id:日期`（跨日活動每一天各一筆）。手動與自動都用它：複製過的不再複製，所以重按、重開都不會重複。待辦複製之後才完成的，不會再補一次（寫在說明裡）。這份紀錄只記 id，不記內容。

## 8. 安全

- **網址等於密碼。** 只存在 `設定.json`（0600），**不寫進任何 `.py`**（`.py` 會被存進 `.history/`，也可能發佈到工作坊）。訊息區、狀態列、`app.log`、錯誤訊息、`Api` 的回傳值、log 都不出現完整網址；token 遮起來。`tests/test_secrets.py` 用一個明顯是假的 token，跑完所有流程掃這些輸出。
- **發佈出去的網頁不含 LINE。** `pages.py` 產生的網頁（私人的和 `發佈/`）都不出現 LINE 的內容；`tests/test_isolation.py` 在快取裡放哨兵字串，跑 `rebuild_all`、`publish`、所有 `build_*`，掃輸出與整個日記資料夾。複製進日記之後，那些字**已經是你日記的一部分**，網頁照常會有；測試也釘住這一點。
- **XSS：** 第 5 節的規則，加上 `tests/test_isolation.py` 掃 `page.html` 沒有不安全的寫法；Python 這一頭回給頁面的 LINE 文字都是 JSON 字串。
- **打包的風險（你要知道）。** 工作坊與 `tools/publish.py` 打包時只略過 `.history`、`.origin`、`.unconfirmed`、`__pycache__`、`.ds_store`；**`設定.json`、`line_cache.json`、`line_copied.json`、`.pid` 都不在裡面**，在「行事曆 2」裡就有可能被打進包。改打包程式在範圍外。做法：檔案權限 0600、放一個 `.gitignore`、在 `CHANGELOG.md` 和這份文件寫「**上傳前先把這幾個檔搬走**」。`tests/` 與 `docs/` 也會進包，所以測試只用假 token（`FAKE-TOKEN-…`），不放任何真資料。

## 10. 設計決定

**L01 LINE 這一層寫成幾個小檔，不塞進 `iplot.py`。**
理由：網址檢查、解析、快取、複製都是純函式或只碰一種東西，各自能不開視窗就測；`iplot.py` 已經 313 行。
沒選：全放 `iplot.py`（難測、難讀）；放進 `diary.py`（LINE 和日記要分開存，之後雙向同步會改它）。
狀態：採用。

**L02 程式裡所有名字讀資料夾名，不寫死「行事曆 2」。**
理由：資料夾名要由你決定，改名不該改程式。`ENV`、`ICON` 這類「身分」常數另外寫死，跟資料夾名無關。
狀態：採用。

**L03 找自己的程序用「指令結尾是資料夾路徑」，不是「含有」。**
理由：舊路徑是新路徑的前綴；「含有」會讓舊版把新程序當自己。新版的做法不依賴舊模組的名字。
沒選：改舊行事曆的比對（範圍外）。
狀態：採用。

**L04 token 檢查：字元集嚴格、長度 20–128。**
理由：字元集決定路徑安全；bot 的測試用 `{40,64}`，但文件沒寫長度，放寬以免它改長度就壞。
狀態：採用。

**L05 `設定.json` 用「讀出來、改一個鍵、寫回去」，保留不認得的鍵。**
理由：現在 `diary.save_root` 整檔覆寫，會洗掉 `"LINE"` 區；之後要加寫入金鑰也不必改格式。
狀態：採用；`diary.save_root` 改成呼叫 `settings.py`。

**L06 型別不對就整份拒收，不跳過單筆。**
理由：悄悄丟掉一筆你看不出來；整份拒收就保持上一次完整的快取，而且說明哪一區壞了。文件承諾型別穩定，所以拒收應該很少發生。
沒選：跳過壞掉的那一筆。
狀態：採用。

**L07 複製之前強制存一份快照。**
理由：現有的 `snapshot` 有 10 分鐘規則（上一份不到 10 分鐘就不存）；你剛改過那欄的話，沒有「複製之前」的版本可找。需求是「要能從 `.history` 找回原本的」，所以複製前必須存。
做法：`diary.snapshot` 多一個 `force`；仍遵守 `history_keep` 的份數上限。
狀態：採用。

**L08 抓網址在背景執行緒，不拿 `Api._lock`。**
理由：4.6 節。
狀態：採用。

**L09 自動複製「每次打開一次」，沒有計時器。**
理由：你選的；iPLoT 沒有常駐程式（D84），行事曆 2 只有開著才有程序；用 macOS 排程要在「行事曆 2」以外放檔，超出範圍。補上漏掉的天數，所以沒開的日子下次打開會補。
沒選：行事曆 2 開著時到點執行；launchd 排程（範圍外）。
狀態：採用。

**L10 自動複製略過私人項目與公開的日子。**
理由：沒人看著，也沒有預覽；私人項目複製進公開的日子，下次「發佈」就上網了。你還不知道「公開」是什麼，所以用最安全的預設。要複製這些，用手動按鈕（有預覽、有警告）。
狀態：採用，等你確認。

**L11 一律用台北日期算「今天前後 400 天」。**
理由：bot 用台北時間算；這台電腦不在台北時區時，邊界才不會差一天。日記的日期與「昨天」仍用這台電腦的本地日期。
狀態：採用。

**L12 沒有截止日的待辦先存進快取，這一版不顯示。**
理由：它不屬於任何一天；放哪裡顯示是另一個設計題，先不做。
狀態：採用；寫進「這次沒做」。

**L13 翻頁補抓有三條節制的規則（4.6 節）。**
理由：頁面每翻一頁、每次 LINE 的資料變了就會重畫，重畫會再叫補抓；沒有節制的話，打開時多一個請求、網址失效時每翻一頁敲一次 bot、斷網時每翻一頁等一次逾時。bot 每個來源每分鐘有次數上限。
沒選：頁面自己決定要不要補抓（頁面沒有時鐘、沒有快取的資訊）。
狀態：採用。用瀏覽器接真的 `Api` 跑過：404 之後翻到 2027 年 3 月，請求數前後都是 2；429 的等待期間一個請求都沒送。

**L14 `Api._lock` 改成 `RLock`。**
理由：自動複製要這把鎖；測試用同步的 spawn 時，它在 `month()`（已經拿著鎖）裡面被叫到，不可重入的 `Lock` 會死鎖。正式使用是另一條執行緒，不會發生，但可重入比叫測試繞路穩。
沒選：把自動複製丟到別的執行緒再做（多一條不必要的執行緒）。
狀態：採用。

**L15 複製時只認 `\n`、`\r\n`、`\r` 當換行。**
理由：`str.splitlines()` 連 U+2028 這類字元都算換行，會悄悄把 LINE 原文裡的那個字元吃掉。複製進日記不該改 LINE 的字。
狀態：採用（`tests/test_line_copy.py::test_only_real_newlines_split_lines_and_other_characters_are_kept_as_they_are`）。

## 11. 之後做雙向同步要改哪裡

- **`id` 對應：** 快取已保留每筆的 `id`；之後 iPLoT 新增的項目要有自己的 id 與「來源」，LINE 回來的 JSON 會多一個「這筆是從 iPLoT 來的」標記——解析現在就忽略不認得的欄位，之後 `line_data.py` 認得它、在合併時不把自己送出去的東西當成新的。
- **寫入金鑰：** 放 `設定.json` 的 `"LINE"` 底下（格式現在就能加欄位）；`settings.py` 已保留不認得的鍵；金鑰跟網址一樣遮蔽。
- **送出佇列：** 新增 `line_push.py`，跟 `line_sync.py` 分開：iPLoT 這邊的變更先寫進「待送出」，送成功才清；失敗下次再送。`line_net.py` 多一個非 GET 的函式，錯誤分類與遮蔽不變。
- **日記本身沒有 id：** 現在的日記是自由文字（`行程.txt` …），不能逐筆對應。要雙向的話，要決定哪些欄位變成「一行一筆、帶 id」，或另外存一份結構化的檔，而不是動 `diary.py` 的格式；`line_copied.json` 已經記了「哪個 id 複製成了哪一天」，可以當對照表的起點。
- **衝突：** 同一筆兩邊都改了，先決定「以誰為準」（建議以最後修改時間，並保留另一邊在 `.history`）。這需要 bot 在 JSON 裡多一個 `updatedAt`（資料格式 version 2）。
- **鎖：** 寫回的動作要沿用 4.6 節的規則：網路在背景，只在寫本機檔時拿 `Api._lock`。
- **自動複製會跟它打架：** 雙向之後「複製進日記」的意義會變（LINE 的內容本來就會出現在 iPLoT 裡），那時要重新決定要不要保留。
